# 收尾自查清单

自查结果按"问题 → 位置 → 建议修改"报告给用户。大的结构改动先确认再动手。改稿任务中，需要回仓库核实或重跑实验的项单独列出（见 SKILL.md §11）。

## A. 叙事闭环

- [ ] 主叙事原型明确（做减法 / 原生重设计 / 开新类别 / 机制拆解），实验提供了该原型要求的证据（见 `oral-patterns.md` §1）。
- [ ] claim–evidence 对照表中每个 claim 都有证据；没有证据的已删除或收窄。
- [ ] 每个正文实验都回答了 intro 中的某个问题；不回答任何问题的已移到附录或删除。
- [ ] N–N–N 对齐：intro 的挑战、method 的设计、实验的证据组、副标题或摘要关键词，数量和措辞一一对应。
- [ ] （可选）标题关键词在正文中作为章节或小节标题出现过一次。
- [ ] 结论回扣了 intro 提出的问题，没有引入新 claim。
- [ ] 只读段首句能读完整个故事。

## B. 门面

- [ ] 标题为"方法名: 副标题"格式（或有意选择的双关标题）；方法名不是硬拼的缩写；副标题含核心洞见、新类别、对应挑战的性质或发现清单之一。
- [ ] 已提醒用户查重名（arXiv / GitHub）；"first" 带有精确的限定语。
- [ ] 摘要按 1:1:1 的均衡思路分配，问题背景不超过 1/3（问题众所周知时约 1/5）；首句是具体问题、"广泛使用但没人拆开看"或贡献先行之一，语境短语之后同一句或下一句就点出问题。
- [ ] 摘要有一句承载核心贡献或发现的句子，没有把多个并列的"核心"散在各处。
- [ ] 摘要的结果具体到比较对象和条件；数字最多一两个。
- [ ] 字数符合会议限制。
- [ ] Intro 最迟第 3–4 句出现具体问题；对已有工作的批评是具体失效条件，并用一个测量值、例子或混淆证据钉住。
- [ ] 如果 intro 提了框定全文的研究问题，论文给出了回答，而且全文只有这一处。
- [ ] Contributions 每条可验证、有对应证据；形式不限（列表、内联编号、一句话或一段总结）。
- [ ] Teaser 图在前两页内，类型与叙事原型匹配；caption 第一句是结论。
- [ ] 没有 "we emphasize" 类元强调；句首 Notably / Importantly 类不超过 3 处，且后面紧跟具体事实；斜体只用于定义概念、少量对比词和分析型论文的小节结论。

## C. 证据呈现

- [ ] 表格高亮规则全文统一，只用一种非绿色系颜色，色块足够浅；只在第一张表说明规则。
- [ ] booktabs、无竖线、表头 ↑/↓、小数位统一。
- [ ] 显著性指标最多出现在正文一两个结果中（一个都不报也可以）；其余已移到附录并在正文引用。
- [ ] 正文没有 pre-registration / locked protocol 之类的流程语言。
- [ ] 每个主比较都写明控制了什么（参数量、预算、数据、调参）；必要时加了更强的基线。
- [ ] 有权衡的 claim（质量–代价、精度–速度）配了前沿图，而不是单个工作点。
- [ ] 每个"为什么有效"的 claim 有敲除实验。
- [ ] 非标准评测协议（如 LLM 评判）做过验证。
- [ ] 泛化 claim 有一个所有方法都没训练过的测试集。
- [ ] 定性图挑的是难例，关键数字标在图上；图和表的 caption 第一句写出了结论。
- [ ] 没赢的结果如实写出：数清楚胜出的比例、用校准过的比较词、写明换来了什么；文字总结不强于表格。
- [ ] Ablation 与 method 组件一一对应。

## D. 文字

- [ ] 防御性句式全文 ≤ 2 处；其余已收窄 claim、集中到 Limitations 或删除。
- [ ] Limitations 放在正文（讨论末尾或结论后），每条是具体的失效条件或开放问题，没有空话。
- [ ] 按 `ai-flavor-blacklist.md` 扫描过每一节，次数在预算之内。
- [ ] 没有未经核实的 "first" / "state-of-the-art"。

## E. 一致性

- [ ] 术语、方法名、模块名、符号全文一致。
- [ ] 命名概念和论点关键词在标题、摘要、intro、结论里原样复用，没有换同义词。
- [ ] 同一数字在 abstract / intro / 正文 / 表格 / caption 中完全一致。
- [ ] 引用格式、标题大小写、公式编号风格统一。

## F. 审稿人视角

以一个严格但公平的审稿人身份通读，回答：

- [ ] 读完 abstract 和 Figure 1，能否一句话复述核心贡献？
- [ ] Baseline 是否够新、够强，比较设置是否公平（相同数据、相同算力预算、相同调参力度）？
- [ ] 最可能被质疑的那一点是什么？正文是否已经用实验或论证提前化解（而不是用防御性句子回避）？
- [ ] 最可能被问的"为什么不用 X"，方法部分或讨论小节里有答案吗？
- [ ] 有没有关键实现细节或超参缺失，导致无法复现？

## G. 投稿格式

- [ ] 页数符合当年 CFP。
- [ ] 匿名化：无作者信息、代码链接匿名、无暴露身份的自引和致谢。
- [ ] 会议要求的 checklist / reproducibility / ethics statement 已完成。
